`test_integration.py` exercises public commands against synthetic task packets
for AG and ZCode. It uses explicit `test_only` and `--no-launch`, cannot prove
native execution, and never reads their Desktop sessions or project data.
Unit mocks, local schema checks and test-only queue entries are not native
acceptance, Office delivery, Helpdesk repair or production activation.

The Windows hidden-launch/focus and reparse tests are infrastructure evidence,
not native model proof. Reuse their evidence only while the tested launcher,
path guard and inputs match. A changed native artifact requires current
independent acceptance; the old core ACCEPT does not cover later source edits.

## Native canary and rollback

Use a fresh owned state directory with sanitized fixtures and Office/RSI
disabled. Check the pinned Fleet payload and launcher before any model call.
Run one audit; retain Graph state, actual Fleet receipts, tested input hashes,
provider identities, model usage and explicit unknown values. Repeat the same
enqueue to verify duplicate handling without another native run.

Before activation retain the preimage of changed source/config and verified
private backup. Stop new work with STOP or disabled config, allow current
owned work to finish or retain its interrupted state, then restore only the
authorized source/config. Never delete state or another session's lease.
Sync common skills from their origin through the existing no-delete overlay;
rules use SyncRulesOnly. ValidateSkills and backup PUSHED/CURRENT are required.

## Existing review: process cost

The owner requested a universal post-delivery audit. It adds one asynchronous
deterministic enqueue to the existing closeout and a fixed background graph:
one history scout under its existing economic gate plus two audit nodes,
each with a native maker and an independent reviewer. There is no new
foreground question, acceptance gate, planner, audit of an audit, transcript
scan, rigid child-agent quota or second repair daemon. Real native usage is
reported from receipts; unknown subscription cost stays unknown.

The Hub producer is an external activation dependency. Until that hook is
implemented and tested by its owner, report the candidate/runtime and the
automatic trigger as separate states. The consumer feed is read-only and is
announced READY to idea-maker only after current acceptance and native proof.
