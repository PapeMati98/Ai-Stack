# Capability Map

Select one primary lens from the decision that must be made, not from a job title.
Use a supporting lens only when it adds a distinct oracle or constraint.

## Selection rules

- Prefer the lens whose decision would still matter if the proposed output format
  changed.
- A supporting lens must have a separate acceptance test. Example: Finance can
  test affordability of a People plan; it should not repeat the same workforce
  analysis in different language.
- If three or more lenses appear necessary, the request is probably a program.
  Use Executive strategy to frame it, then compile bounded work through Agent
  Graph instead of loading all references into one response.
- If the real task is legal, tax, security, privacy, accounting, regulated HR,
  data governance, media generation, or software delivery, route directly to the
  specialist rather than forcing a business lens.
- For cross-functional personal branding, B2B acquisition funnels, and investor outreach packages, route to the Personal Brand, Marketing & Sales playbook in [dzial-marka-marketing-sprzedaz.md](dzial-marka-marketing-sprzedaz.md) to orchestrate specialist skills under T2 consent gates.

## Shared evidence discipline

For every lens:

1. Label observed facts, user-provided constraints, assumptions, and hypotheses.
2. Define units, population, time window, source, and freshness for material
   numbers.
3. State what evidence could reverse the recommendation.
4. Convert recommendations into an owner, next action, decision date, and proof.
